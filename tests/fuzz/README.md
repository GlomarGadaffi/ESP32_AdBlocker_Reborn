# Fuzz targets

Coverage-guided fuzzing (libFuzzer) of the two parsers that consume bytes the
device does not control:

| target | code under test | what feeds it on the device |
| --- | --- | --- |
| `fuzz_rule_parse` | `main/domain.c` — `rule_parse_next`, `rule_apply_feed_policy`, `domain_normalize`, `domain_extract_token` | every line of every third-party blocklist feed, and the custom-rules textarea |
| `fuzz_dns_wire` | `main/dns_wire.c` + `dns_extract_qname` — `dns_skip_name`, `dns_resp_min_ttl`, `dns_rewrite_answer_ttls`, `dns_decompress_name` | every client query and every upstream reply (or anything spoofing one) |

Both harnesses copy the input into an exact-size heap buffer, so a one-byte
over-read that the firmware's 512/1500-byte buffers would silently absorb is
an AddressSanitizer report here. They also assert the parsers' documented
contracts (offsets never leave `[0, len]`, tokens point inside the line, a
tiny output buffer truncates instead of overflowing), so an assertion failure
is a finding too.

## Running

Needs clang with compiler-rt (any LLVM release tarball works, no root
required). On this project's Windows box that is WSL with `~/llvm`:

```sh
export PATH=$HOME/llvm/bin:$PATH
sh tests/fuzz/build.sh                      # -> tests/fuzz/out/fuzz_*
tests/fuzz/out/fuzz_dns_wire  tests/fuzz/corpus/dns_wire  -max_len=1500 -jobs=4 -workers=4
tests/fuzz/out/fuzz_rule_parse tests/fuzz/corpus/rule_parse -max_len=512 -jobs=4 -workers=4
```

Crash inputs land in the working directory as `crash-<sha1>`. To reproduce
one without libFuzzer (plain gcc + sanitizers):

```sh
FUZZ_STANDALONE=1 CC=gcc sh tests/fuzz/build.sh
tests/fuzz/out/fuzz_dns_wire crash-...      # or a whole directory
```

`build.sh` honours `$CC`, `$CFLAGS`, `$LIB_FUZZING_ENGINE`, `$OUT` and `$SRC`,
which is the OSS-Fuzz / ClusterFuzzLite build contract — a
`.clusterfuzzlite/build.sh` that just calls this script is all a CI fuzzing
job would need.

## Corpus

`corpus/*` holds hand-built *valid* seeds (real-shaped queries, compressed
answers, CNAME chains, NXDOMAIN+SOA, hosts/AdGuard rule lines) generated by
`gen_corpus.py`. Add any fixed crash's input to the matching corpus dir under a
`regress_*` name so the bug stays covered — `regress_soa_rdlen_oob` is the
first: an NXDOMAIN whose SOA declared an rdlen past the end of the packet,
which read the SOA minimum from 20 bytes beyond the buffer
(`dns_resp_min_ttl`, fixed in the same change that added these targets).

Deterministic unit tests for the same code live in `tests/dns_wire_test.c`
and `tests/rule_parse_test.c`.
